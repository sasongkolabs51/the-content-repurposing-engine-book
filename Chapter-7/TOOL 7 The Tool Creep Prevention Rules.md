## TOOL 7: The Tool Creep Prevention Rules

**Purpose:** A decision framework for when someone (or your own 11pm browsing) suggests adding a new tool to your stack. Prevents the slow accumulation of subscriptions and complexity that turns a clean pipeline back into a tab nightmare.

**Time needed:** 2 minutes per decision.

---

### The "Do I Need This Tool?" Decision Tree

A new tool enters your orbit. Before you sign up, run it through these gates:

---

**Gate 1: Does it replace a manual step I currently do?**

☐ Yes → What step? _______________ → Proceed to Gate 2.
☐ No, it's "nice to have" → **STOP. Don't add it.** Revisit in 3 months if the need becomes real.

---

**Gate 2: Does it integrate with my existing pipeline, or does it add a new handoff?**

☐ Integrates (replaces a step within my current flow) → Proceed to Gate 3.
☐ Adds a new step / new tab / new login → **Probably don't add it.** Unless it eliminates 2+ other steps.

---

**Gate 3: Can I trial it for free before committing?**

☐ Yes → Trial for 2 weeks. Run one full sprint cycle with it. Then decide.
☐ No (paid only) → **Don't buy it yet.** Wait for a free trial or a clear ROI case.

---

**Gate 4: After the trial, did it save me at least 10 minutes per sprint?**

☐ Yes → **Add it.** Update your Workflow Diagram. Update your prompts if needed.
☐ No → **Don't add it.** The complexity cost outweighs the time savings.

---

**Gate 5: Am I adding this because I actually need it, or because I'm procrastinating on the actual work?**

☐ Actually need it → Add it.
☐ Procrastinating / shiny object syndrome → **Close the tab. Go run a sprint.**

---

### The "One In, One Out" Rule

If you add a new tool, you must remove or replace an existing one. Your total tool count should not exceed **4–5** for the entire pipeline (creation tool + AI tool + Hub/document tool + scheduler + email platform).
